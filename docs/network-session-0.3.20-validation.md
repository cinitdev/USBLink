# 断流后残留 USB 会话：Windows 0.3.20 / Mobile 0.3.35

日期：2026-11-18。用户反馈手机断流后电脑设备消失，随后手机重新在线，但 WebUI 保留旧电脑会话，电脑手动连接失败；只有手机断开会话或切换共享才能恢复。

## 代码原因与修复

原 `UsbIpServer.releaseReplaced` 只接受经过认证的桌面进程替换或退出。TCP 连接没有及时收到 FIN／RST 时，手机 socket 和 `imported` 占用仍在；同一桌面进程恢复网络后仍是同一个实例，不能触发清理。新的导入会被拒绝。这是从代码确认的遗漏路径，没有据此断言用户每次断流都来自同一种系统原因。

新增 `USBLINK6` 只读查询：请求包含随机 nonce、原 USB/IP 通道两端端口及 HMAC；响应包含桌面进程实例、当前应用阶段、通道状态，并把 nonce、端口和响应共同认证。IP 从当前已认证查询连接的实际端点取得，服务端只接受手机 USB/IP 3240 端口，不接受客户端任意指定其他 IP。

电脑以 `GetTcpTable` 读取完整 IPv4 TCP 表，匹配两端地址和端口，支持驱动拥有的连接。SYN／ESTABLISHED 视为存在；CLOSED／关闭阶段或成功查询后无匹配才视为结束。读取错误、未知状态、表大小异常返回未知；读取期间表增长只重读只读快照，不执行任何 USB 命令。没有按流量空闲时长踢出会话。

手机每 5 秒检查旧通道，手动导入前也检查一次。只有认证结果确认桌面 ready 且该旧通道已结束才调用现有会话清理，保留共享监听和配对。导入等待旧会话及导入占用释放，提交一次正常导入；旧回调检查具体 Session 对象，不能清理新会话。原进程退出／更新处理保留。新协议不可用时只读回退旧协议，不能把回退或超时视为旧通道消失。

## 定向验证

- Windows `cargo test --offline transport`：3 项通过（另 1 个跨语言检查按标记独立执行）。包括四元组／关闭状态判断、真实 Windows 空闲 TCP 与本地关闭且对端仍开着的区分、认证及端口绑定。未运行全部 Rust 测试。
- `DesktopOwnerTestMain`：旧协议 5 组、新传输协议 7 组通过，包括错误密钥、重放 nonce、错误端口、非法阶段／状态、旧桌面返回。
- `OwnerLifecycleTest`：61 项断言通过。模拟保持旧 socket 未关闭但电脑认证报告已结束；同一桌面进程一次手动导入成功、旧 adbd 与客户端通道关闭、后台能清理首次查询失败的会话、正常／未知／未就绪会话不会被替换、后台不建立新连接、后续观察不清理新连接。保留已有进程更新与退出场景。
- Rust `desktop_transport_java_interoperability`：实际 Rust 响应与 Java 请求在本机回环互通通过。
- 沙箱内首次 Java 旧协议回环测试超时；经权限允许后在沙箱外运行，同一源码通过。没有为了通过测试增加生产超时或重试。

没有连接或改变真机网络、关闭当前共享、USB 重挂载、安装新版或执行传输压测。以上是本机生命周期／系统 API 和协议互通验证，仍需用户用两端新版本观察实际网络中断后的行为。网络仍不通、认证失败或电脑通道确实仍存在时继续保护会话，不宣称所有网络故障都会自动恢复。

## 本地安装器临时文件错误（2026-11-18）

用户从 `release/USBLink-0.3.20-x64-Setup.exe` 启动时出现 NSIS `Error writing temporary file. Make sure your temp folder is valid.`。TEMP/TMP 指向的目录存在且普通进程可写，安装器校验和与构建输出一致。文件继承了沙箱工作目录的 Low Mandatory Level；读取实际出错进程的 TokenIntegrityLevel 得到 `S-1-16-4096`（Low）。

经授权，在沙箱外仅对发布副本和本次 NSIS 构建输出执行 `icacls <具体安装器文件> /setintegritylevel M`，回读均为显式 Medium Mandatory Level。未更改工作目录、TEMP 或系统权限。两份文件的 SHA256 仍为上表值。重新启动同一发布副本，已实际观察到中文“欢迎使用 USBLink 安装程序”页面，原 NSIS 错误不再出现。停留在欢迎页，没有执行安装、退出当前 USBLink 或断开设备。

这是本地构建产物的 NTFS 完整性标签问题，无需修改 NSIS 的 TEMP 路径或改为管理员安装。以后从带 Low 标签的沙箱目录交付本地安装器，应在获准的普通用户环境中检查最终 EXE 的标签；如继承 Low，仅修正最终产物并验证启动。不要递归修改工作目录/TEMP 的权限，也不要以管理员运行绕过检查。文件标签不属于 EXE 字节内容，不需要为此重建 Android 模块或更改版本、校验和。

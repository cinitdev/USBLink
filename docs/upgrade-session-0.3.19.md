# 桌面更新后旧手机会话占用修复

2026-11-08，Windows 0.3.19 / USB 实验模块 0.3.21，本地构建。

## 原因与范围

安装器经用户确认强制关闭桌面程序，跳过正常退出清理。新版桌面启动仍会清理驱动挂载，但原模块只靠 USB/IP TCP 读写退出释放唯一导入锁。如果手机侧旧 socket 尚未结束，电脑当前挂载列表为空也不能证明手机已释放，新的导入会被旧会话占用拦截。

本次从代码中确认了这一生命周期缺口，并用保持旧 USB socket 打开的本机回环场景复现；没有在用户 K70 上观察安装器更新过程，因此不宣称已证明所有现场断开的唯一原因。

## 修复方式

- 复用 TCP 3241 增加只读 USBLINK5 观察：每个桌面进程一个随机 128 位标识，响应包含当前启动／就绪／退出／失败状态，由配对 HMAC 与本次随机挑战绑定。标识只存在进程内，不使用型号或 IP 充当持久身份。
- 手机在导入时记录已认证标识，仅活动且支持该能力的会话每五秒检查一次。确认同一个进程正在退出，或另一个进程已进入 Ready 后，释放被确认的旧会话。Ready 仍由现有单实例锁和双向启动清理控制。
- 没有响应、认证失败、旧协议、启动中或清理失败，都不据此中断现有 USB。没有无流量超时、共享操作重放或自动挂载。
- 若用户已点击连接，接收此次唯一导入前先做相同核验，等待旧 socket、读写线程与导入锁清理完成。其他仍在使用的电脑不会因为新导入请求而被抢占。
- 分享开关、网络与 adbd 不因桌面替换而重启。强杀后桌面未重开且 TCP 未结束时，手机可能暂时仍显示旧会话；新进程确认就绪后才能安全识别替换。

## 使用与兼容

两端都更新后新建的连接具备此保护。旧桌面缺少认证进程标识时，仅维持原有 TCP 关闭语义，不承诺新行为。更新模块并按原模块要求重启会结束之前的旧后台连接，配对与历史保留；之后重新手动连接。不安装／操作真实手机，不启动桌面 ADB，不变更 USB 模式。

## 验证

- Java：5 项认证场景（正确、错误密钥、旧 nonce 重放、非法阶段、旧协议）；19 项旧会话交接检查（保持旧 socket、单次新导入、正常／未知／启动中／失败时不抢占、退出后台释放）。
- Rust：进程标识稳定性、挑战与配对认证；实际 Rust 响应与 Java 查询端本机联调。
- 现有模块生命周期／认证回归 63 项通过，覆盖常规断开、共享启停、历史、网络状态观察与旧客户端路径。

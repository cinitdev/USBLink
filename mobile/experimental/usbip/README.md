# 用户态 USB ADB 可行性试验

这是独立的开发试验，**不会加入生产模块、替换已安装模块或添加启动项**。完整目标仍是 MTP + ADB；本试验只验证 USB ADB 枚举和真实传输，不能称为已经实现手机完整 USB 共享。

2026-10-07：K40 已通过一次明确授权的新手动挂载，完成 Windows USB ADB 枚举及 64 MiB 推送/拉取、三处 SHA-256 一致、单设备断开和共享恢复。详见[真机记录](../../docs/userspace-usb-first-trial.md)。未测试 APK 安装或 Android Studio 实际调试，MTP 未实现。

## 结构和边界

- 手机 Root `app_process` 启动用户态 USB/IP 1.1.1 服务，不需要手机 USB/IP 内核模块，不修改 Gadget/UDC。
- 手机复用已安装 USBLink Mobile 0.2.2 的受保护 adbd 后端。通过原有 Root 控制套接字临时启用共享，可能重启 adbd；结束后恢复原共享意愿。系统 RSA 认证保持原样。
- 只监听 `usblink0` 的实际地址、TCP 3240，只接受已确认的试验电脑地址。IPv4/IPv6 规则拒绝其他接口；共享停止或网卡消失会停止服务。等待挂载最多 15 分钟；第一次挂载成功后单独计时 30 分钟，不因后续连接而延长。
- 虚拟设备 bus ID `99-1`，每次启动有新的来源路径，序列号加 `USBLink-` 前缀，避免混同仍连接的物理设备。协议身份 `18d1:4ee7` 仅用于本地驱动互通试验，发布前必须解决正式 USB 身份与驱动绑定。
- Windows 复用既有 usbip-win2 >= 0.9.8.0。手动一次 `--once` 挂载，禁止自动补试；不得断开试验前已有的挂载，不启动/替换电脑 ADB server。
- 没有 MTP、Fastboot、外接 USB 或 U 盘支持。没有把 ADB TCP 地址注册到电脑 ADB server。

## 真机验证顺序

这些脚本仅供明确授权的独立试验，不是安装模块的必需步骤。执行前设置 `USBLINK_TEST_SERIAL` 为已确认的物理手机序列号；不设置则立即退出，仓库不保存开发者手机序列号。`transfer.mjs` 会使用对应的 `USBLink-` 虚拟序列号，型号校验仍限定原始 K40 试验范围。不要在发布检查中运行这些真机脚本。

1. 确认唯一授权的 K40、Android 12、现有手机模块、电脑虚拟网卡与驱动版本，并记录已有挂载。
2. 在主机执行 `build.ps1`：先跑独立字节流测试，再编译 DEX JAR 到 `mobile/build/usbip-probe/`。不修改正式发布包。
3. 将 JAR 和启动脚本放到手机 Root 私有目录 `/data/adb/usblink-usb-probe`。从已有 USB ADB 启动临时脚本；诊断 ADB 只用于部署和回收，不承载试验 USB/IP 数据。
4. 核验手机本地状态、Root 导出记录与至少两次稳定的网络设备记录一致，再提交唯一一次 `usbip attach --once`。保持现有导入不变。
5. 读取 Windows PnP 枚举结果，以及现有 ADB 对 `USBLink-` 序列号的发现/授权。只有确认实际通信，才做临时文件传输和哈希比较。APK 安装需要明确的测试 APK，不能替用户挑选安装未知应用。
6. 校验本次导入的服务器、bus ID、VID/PID、本地端口后，仅断开这个导入；创建手机私有目录的 `stop` 文件。确认试验进程/监听退出，原共享关闭状态、adbd 临时属性与防护规则恢复。

如果现有手机和电脑不在同一网络，可用 `host-link.mjs` 启动额外的 EasyTier `--no-tun` 实例，仅监听 `127.0.0.1:33240`。它通过手机现有加密网络转发到虚拟 USB 服务，不修改双方保存的配对。必须使用与手机一致的 AES-256-GCM；默认 AES-GCM 算法不同，会出现“能看到节点但数据解密失败”。配对信息只经已授权的 ADB 读取到进程内存和子进程环境，不写文件或命令行。

USB/IP 工具的端口必须使用全局参数 `--tcp-port 33240`，不能写成 `-r 127.0.0.1:33240`。试验期间仅临时将手机 EasyTier 的 TCP 白名单从 `3241-3242` 改成 `3240-3242`，退出恢复，遇到外部修改保留恢复记录。

`preflight.mjs` 使用临时回环转发端口 33241 验证手机的 HMAC 在线响应，并将三次网络 USB 导出记录与 Root 诊断读取的当前来源记录比较。该脚本不提交挂载。

## 失败恢复

正常停止通过私有 `stop` 文件触发，避免强杀中断恢复。Java `finally` 与脚本退出处理会停止监听，并将本试验临时开启的共享交回原模块恢复；恢复失败保留 `restore-sharing` 记录，不允许覆盖该记录开始第二次试验。控制服务继续提供其原有恢复能力。

这些恢复措施不等于任意强杀/掉电场景已验证。任何 Windows 驱动错误、未知导入身份或手机恢复失败，都应停止挂载试验并保存诊断，不能通过重复挂载掩盖问题。

协议依据：[Linux USB/IP 协议](https://www.kernel.org/doc/html/latest/usb/usbip_protocol.html)。代码为独立实现，未复制示例项目代码。

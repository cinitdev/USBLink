# 0.3.30 调试服务启动修复

日期：2026-11-14。用户截图为真我 GT5 240W（RMX3823）、Android 16。WebUI 显示 USB 调试已开启，而共享报错“请先在开发者选项开启 USB 调试，等待系统调试服务运行”。

## 原因与边界

已定位唯一报错路径：TcpAdb.start 先通过 USB 调试／RSA 检查，却把任何非 running 的 `init.svc.adbd` 都报成需要开启 USB 调试。截图不能确定该机属性当时是 stopped、restarting、stopping 还是空值，也不能证明该 ROM 的停服原因。

核对 AOSP Android 16（android-16.0.0_r1）官方源码：`system/core/init/service.cpp` 的 Service::Restart 对未运行且不在重启中的服务调用 Start；`packages/modules/adb/daemon/main.cpp` 在没有 USB 传输且没有正数端口时会选择默认 TCP 监听。因此不只是删除前置判断，还需记录原停止状态，在关闭时先停服务、确认后再恢复原端口，避免激活不需要的默认监听。

修复允许已授权且状态为 stopped 的服务受保护地启动一次，running 保留原流程。正在切换／未知状态明确报错；监听未确认时保持 pending，超时后给出实际服务状态，不自动补试。启动前二次确认授权、配置和原服务状态，防护／身份验证不放宽。不改变 USB 调试系统开关、RSA 或 adbd Root 权限。

恢复记录为版本 2，兼容读取原版本 1（原先仅允许 running）；原停止状态在同一次启动内恢复，跨重启不重放旧状态。需要降级时应先关闭共享并完成恢复，旧模块不识别版本 2 的恢复记录。

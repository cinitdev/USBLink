# K40 用户态 USB ADB：真机试验记录

日期：2026-10-07。目标手机：Redmi K40，Android 12，APatch。原有 Windows USB/IP 导入与手机正式模块保留。

**最新结论：用户明确授权的第二轮手动验证通过 USB ADB 枚举、64 MiB 双向传输与 SHA-256 校验；仍未实现 MTP，也未进行 APK 安装或 Android Studio 实际调试。**

## 已确认的结果

1. 手机上独立 DEX JAR 经 Root `app_process` 运行，提供用户态 USB/IP ADB 接口；没有加载内核模块、刷内核或改 Gadget/UDC。
2. 使用手机现有 EasyTier 网络和 Windows 临时无 TUN 客户端建立加密数据通道。手机和电脑原来保存的配对属于不同网络，因此没有改其原配置；临时客户端的加密算法须显式设置为与手机相同的 AES-256-GCM。
3. 挂载前通过手机 HMAC 在线验证，连续三次核对导出 bus ID `99-1`、`18d1:4ee7`、当前服务来源路径与 Root 读取的来源记录一致。
4. 只提交一次 `usbip --tcp-port 33240 attach --once --terse -r 127.0.0.1 -b 99-1`，返回本地端口 2。
5. Windows PnP 确认新设备状态为 `OK`、类别 `AndroidUsbDeviceClass`、名称 `Android ADB Interface`，设备实例位于 `USB\VID_18D1&PID_4EE7\USBLINK-<设备序列号>`。
6. 电脑已有 SDK ADB 自动发现带 `USBLink-` 前缀的新序列号，状态为 `device`，真实返回型号 `M2012K11AC`、产品 `alioth`。没有执行 `adb connect`，没有启动第二个电脑 ADB server，也没有替换 SDK。

上述证据说明：**手机缺少 USB/IP 内核模块时，用户态协议服务仍可通过现有 Windows 驱动枚举出可通信的 USB ADB 接口。** 这不是完整手机 USB/MTP 功能完成的证据。

## 大文件测试：本轮未通过

通过新虚拟接口推送一个随机 64 MiB 文件。传输持续约 253 秒；期间实测手机文件增长到 61,210,624 字节，接口仍在线。

随后触发了原试验服务“从启动开始 15 分钟”的硬期限。准备网络已消耗大部分期限，服务约于 13:23:34 主动结束并恢复 adbd；ADB 报告发送计数 67,108,864 字节后返回 `failed to read copy response: EOF`，退出码为 1。恢复后临时文件不存在，无法完成远端哈希校验。

**不能把发送字节计数当作传输成功，也不能据此宣称已解决原来的 APK 安装掉线问题。** 停止时刻与代码中主动恢复期限一致，但本轮没有得到一次完整的大文件传输成功结果。

已将试验期限修正为：等待首次挂载最多 15 分钟，首次成功挂载后另计 30 分钟。到期会明确写入退出原因；后续连接不会自动延长期限。用户随后明确回复“开始一次新的手动验证”，才进行第二轮部署和一次新的 `--once` 挂载；没有自动补试。

## 第二轮：完整双向传输通过

使用修正计时的 JAR，同样通过 HMAC 在线验证和三次导出身份核对后，仅执行一次手动挂载。虚拟接口保持在同一 ADB transport（8）中完成以下操作：

| 检查 | 结果 |
| --- | --- |
| 实际型号读取 | `M2012K11AC` |
| 推送随机文件 | 67,108,864 字节，成功退出，约 253.6 秒 |
| 手机文件 SHA-256 | 与电脑原文件一致 |
| 拉回同一个文件 | 67,108,864 字节，成功退出，约 104.2 秒 |
| 拉回文件 SHA-256 | 与原文件、手机文件一致 |
| 同一挂载持续性 | 传输期间没有再次提交 attach，没有 EOF |
| 临时数据文件 | 成功通过虚拟接口删除 |
| 单设备断开 | 新鲜核对端口 2 的服务器、bus ID 和 VID/PID 后，只提交一次端口 2 detach，驱动确认成功，端口 1 保留 |

三处一致的 SHA-256：`41ad63d348071d28798b10914cb34f1817faa711342f99a0d42ee18f35402677`。

自动记录位于本地构建目录 `mobile/build/usbip-probe/transfer-result.json`。数据阶段为 13:30:44–13:36:43（Asia/Shanghai）。本轮经过临时加密网络路径，实测吞吐约上行 0.3 MiB/s、下行 0.6 MiB/s，不能据此宣称性能已满足日常开发或所有网络条件下可靠。

## 退出核对

- 临时 Windows 端口 2 已消失；原来的端口 1 / bus ID `1-6` 仍存在。
- 原诊断设备回到 ADB 列表；新 `USBLink-` 序列号已经移除。
- 手机共享恢复到初始 `enabled=false`、`active=false`，系统 adbd TCP 临时属性恢复为空。
- 手机 3240 / 3242 / 15558 监听已停止，EasyTier TCP 白名单恢复 `3241-3242`。
- 手机试验进程和 Windows 临时 EasyTier 进程均已退出；配对配置未替换。

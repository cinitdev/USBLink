- 只使用电脑已运行的 SDK ADB 与现有 K70 虚拟 USB 挂载，usbip-win2 为 0.9.8.1。未新建 ADB 服务、执行 USB 导入、重启或升级手机。

- 手机 `/dev/zero` 向电脑传输 64 MiB：55.03 秒，收到完整长度并验证全零内容，退出码 0。
- 电脑向手机 `/dev/null` 发送 64 MiB：33.58 秒，ADB 上传命令退出码 0；不写入手机文件。该方向是完整提交／退出检查，不是落盘文件的哈希验收。
- 同时只读查询模块状态及 Windows 挂载。上传期间两次 ADB 状态查询超过 8 秒；传输结束后原模块会话 ID、虚拟 USB 挂载与 ADB transport ID 保持一致。

## 可控复现与修复

旧 `UsbIpServer.Session.run` 在 USB 请求分发线程内同步写入 adbd。当对端暂时不接收上传数据时，这次写入会阻塞分发，后续 IN 读请求及 UNLINK 取消也无法处理。

新增 `duplexBackpressure` 使用真实回环套接字和收发缓冲限制：先提交 1 MiB OUT，模拟 adbd 暂停接收、同时发出应答，随后提交 IN。正确实现必须在 OUT 完成前交付应答，允许对端继续推进。旧代码在该 IN 响应处超时；已在沙箱外再次确认，不是沙箱阻止连接。

修复使用单独保序的写入线程，最多保留 32 个请求／4 MiB 上传数据。USB 请求分发继续处理 IN 和 UNLINK。完成写入后才发送对应成功响应。尚未开始的排队写入可以取消，正在进行的写入报告取消未生效并继续完成，避免截断 ADB 字节流。关停先关闭双端套接字，再取得队列锁并唤醒／退出线程。

保留一个会话的首个终止原因，防止清理触发的后续 SocketException 覆盖它。诊断固定为时间、原因代码、中文说明、主动操作标记和已完成字节数；不记录手机序列号、配对秘密、命令、文件名或传输内容。手机界面保留当前后台进程最近一次非主动中断；新会话成功或正常关闭共享不会伪造当前故障，历史提示与当前会话列表分开。

网络观察失败仍会撤销已有会话；没有放宽防护、过期验证或添加自动重挂载。如果后续诊断记录为 NETWORK_UNAVAILABLE，需要继续对准当时网络观察链路，不能仅凭本次修复排除其他原因。

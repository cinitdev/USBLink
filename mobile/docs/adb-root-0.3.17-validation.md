# Mobile 0.3.17 ADB Root 来源与兼容层

> 历史归档：用户已在 2026-11-04 要求移除 adbd Root 运行模式；0.3.18 删除该实现。本页仅记录旧版行为与当时验证，不是当前使用指引。

日期：2026-11-04。仅更新手机模块；桌面程序不需要本次更新。

## 行为与边界

- 运行中 adbd 的真实 UID、init 父进程、启动时间及可执行文件共同确认身份。支持标准 adbd、Sui 的 adbd_real 与本模块的暂存原始副本；不读取 KSU 或其他管理器的 ADB Root 功能记录。来源无法核验时不给出可开启权限的按钮。
- UID 0 且没有本模块同一开机日志、已加载的专属预加载库和仍属于本模块的挂载时，显示外部 Root，隐藏开关；后台同样拒绝开启／关闭请求。
- 新兼容模式首次手动开启。旧版 v1 默认开启不会自动授予更强的兼容能力；已明确开启的 v2 偏好持久保留。启动时先检测外部 Root，存在时不接管。
- 以 Sui 的包装程序与 LD_PRELOAD 方案实现；原生组件 GPL-3.0-or-later，ZIP 附带源码、构建脚本、上游提交与许可。对原系统 adbd 及其 APEX 库做易失副本和可撤销挂载，不改写系统分区文件。
- 同一个 ZIP 按安装器记录的管理器类型选择 Magisk magiskpolicy、APatch magiskpolicy/apd 或 KernelSU ksud，Root 安全域从当前实际 Root 进程读取，支持 magisk / su / ksu。此安装器标记只选择操作工具，不能证明 adbd 已有 Root。
- 目前仅 ARM64、Android 12+、动态链接 `/apex/com.android.adbd` 布局。ROM 的动态加载或 SELinux 拒绝会显示具体失败，不再把 ro.debuggable=0 一律说成 ROM 不支持。
- 仅添加 adbd 动态转换、原可执行文件重新执行及安装应用需要的定向 SELinux 允许项，不改变强制模式、系统 USB 调试或 RSA 认证。允许项保留到重启，关闭时不删除可能被其他模块共用的规则。
- 关闭先取消本模块预加载行为，重启 adbd 并核验 UID 2000，然后移除自己的顶层挂载、恢复原 service.adb.root。任何不明或外部变更不覆盖；失败保留来源／恢复日志，未确认降权不恢复远程共享。整个过程不重启手机、不自动重新挂载电脑 USB。
- 每次服务切换会中断现有 USB／网络调试；电脑需要手动重连。adbd 本身已停止时允许清理本模块残留，但不擅自开启系统调试。

## 数据

- `/data/adb/usblink/adb-root-preference.json`：本模块偏好，v2。
- `/data/adb/usblink/adb-root-recovery.json`：同一开机的操作与所有权日志；不以这个文件单独认定当前进程归本模块。
- `/dev/usblink-adbd/<随机标记>/`：原生组件运行副本、启动配置和挂载身份，重启自然消失。下一次准备会回收未挂载且未被运行进程使用的旧副本。
- v1 恢复记录归档为 `adb-root-recovery.legacy.json`；无法证明来源的旧 Root 保持只读，不尝试撤销。

## 验证范围

- 118 项 Java 所有权／生命周期检查通过：外部权限读写拒绝、单次开启与关闭、来源标记丢失、外部挂载、属性／策略失败模拟、UID 未降权、清理失败、同一开机接管记录和旧偏好迁移、系统服务停止时清理。
- 8 项 WebUI API／系统环境检查通过；22 个安装场景及 6 个管理器 BusyBox 查找场景通过，安装器记录的管理器类型也逐一检查。
- NDK ARM64 原生组件与 Java／DEX、WebUI 生产构建通过；浏览器示例确认外部 Root 无开关、本模块 Root 可切换。此处实例均为显式预览，未执行真实权限操作。

本次没有连接、刷入或重启手机，没有执行真实 adb root，也没有 K70 / Android 15 或三管理器真机切换结果。主机状态测试及编译通过不能证明 ROM 动态加载、策略修改、挂载传播及 Android Studio 重连已在真机成功。

# Mobile 0.3.23：历史显示分页纠正

日期：2026-11-08。保留 1000 条记录，每页默认显示 100 条，不改变命令和手机返回内容采集。Windows 版本维持 0.3.19，TCP 开发源码版本为 0.2.13。

## 修正范围

- 后台保留上限恢复为 1000；重载旧历史不裁剪为 100。读文件上限为 32 MiB，以容纳有界的长命令和返回内容。
- 后台每次最多提供 100 条，并继续保持约 40 KiB 的历史响应预算，兼容既有控制通道。
- WebUI 默认显示完整的 100 条：遇到长记录，以游标分批读取直至填满或没有更早记录。续页从最后已显示的记录开始，不跳过超额批次；筛选覆盖全部保留历史。
- 保留 epoch、页面请求序列和静默刷新判断。清空、切换筛选或离开页面后，不继续应用旧批次；中途失败保留已确认页面并允许重试。
- 0.3.22 是误解需求的旧本地构建；若其已在手机淘汰记录，0.3.23 无法恢复已不存在的数据。不操作手机数据或重放 ADB 命令。

## 定向检查

- AdbHistoryTestMain：60 项通过，包括 1000 条轮转与重载、字节受限分页游标及原有分类／TCP 返回观察。
- AdbResponseTestMain：25 项通过，包括完整保留旧文件的 1000 条、默认读取 100 条短记录、有更早页以及既有返回解析。
- WebUI history.test.mjs：6 项通过，包括超过 100 条预览、长输出分批合并、续页无遗漏／重复、清空失效和离开取消。
- 浏览器使用 125 条示例记录（含长输出及 40 KiB 单次读取限制）：进入历史显示 100 条，下一页显示剩余 25 条，返回最新恢复 100 条；保存上限始终显示 1000，错误日志为空。未使用真实手机数据。
